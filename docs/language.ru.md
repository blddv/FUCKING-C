# Fucking C 2.1 / C++20 — семантика

## Исходный код

UTF-8, токены разделяются пробельными символами; BOM допускается. Все значимые символы принадлежат C-токенам из таблицы README. Идентификаторы и литералы также C-only. Комментариев нет.

Лексер принимает кириллические `С/с` как псевдонимы латинских `C/c`. Известные разложенные написания C с acute, circumflex, dot above, caron и cedilla приводятся к `Ć/ć`, `Ĉ/ĉ`, `Ċ/ċ`, `Č/č`, `Ç/ç`. Это нормализация **конечного алфавита языка**, а не универсальная библиотека Unicode NFC. Остальные украшения распознаются только в точной заданной форме.

Используемые combining marks: macron U+0304, diaeresis U+0308, tilde U+0303, low line U+0332, long stroke overlay U+0336, breve U+0306, ring above U+030A. Литералы/имена используют C with hook `Ƈ` U+0187, `ƈ` U+0188 и C with stroke `Ȼ` U+023B.

## Грамматика

Имена LET/FN и прочие ниже — обозначения видов токенов, не альтернативные слова исходника. Соответствия показывает `./fc syntax`.

```text
program       = statement* EOF
statement     = LET IDENT ASSIGN expression SEMI
              | FN IDENT parameters block
              | IF condition block (ELSE (if-statement | block))?
              | WHILE condition block
              | FOR LPAREN IDENT IN expression RPAREN block
              | RETURN expression? SEMI
              | BREAK SEMI | CONTINUE SEMI
              | block
              | expression (ASSIGN expression)? SEMI
block         = LBRACE statement* RBRACE
condition     = LPAREN expression RPAREN
parameters    = LPAREN (IDENT (COMMA IDENT)* COMMA?)? RPAREN
primary       = NUMBER | STRING | TRUE | FALSE | NULL | IDENT | BUILTIN
              | LPAREN expression RPAREN
              | LBRACKET (expression (COMMA expression)* COMMA?)? RBRACKET
              | FN parameters block
postfix       = primary (call | index)*
call          = LPAREN (expression (COMMA expression)* COMMA?)? RPAREN
index         = LBRACKET expression RBRACKET
```

Присваивание — инструкция, не выражение. Слева допустимы только имя или индекс. Правую часть вычисляют до контейнера и индекса левой части. Параметры уникальны. `return` допустим только внутри функции, `break/continue` — внутри её собственного цикла; вложенная функция не может управлять циклом вызывающего кода.

## Выражения

Приоритет от низкого к высокому:

1. `or`
2. `and`
3. унарный `not`
4. цепочки `== != < <= > >=`
5. `+ -`
6. `* / // %`
7. унарные `+ -`
8. `**` — правая ассоциативность
9. вызов и индекс — слева направо

`2 ** 3 ** 2 = 512`, `-2 ** 2 = -4`, `(-2) ** 2 = 4`. Цепочка сравнений вычисляет каждый необходимый операнд ровно один раз; после первого false вычисление цепочки прекращается. `not a == b` означает `not (a == b)`.

Ложные значения: false, null, ноль, пустые строка и список. Остальные истинные. `and/or` возвращают операнд с коротким замыканием, `not` возвращает bool.

## Типы

- **int:** знаковое целое до 4096 значащих бит; реализовано `boost::multiprecision::cpp_int`. Переполнения по модулю 256 или 2⁶⁴ нет.
- **float:** конечное IEEE 754 binary64. `/` даёт float. Деление двух больших int округляется в binary64 непосредственно, без промежуточного переполнения преобразованного знаменателя. Поддерживаются субнормальные значения и отрицательный ноль. NaN и Infinity отвергаются.
- **bool:** самостоятельный тип, не число. `true == 1` — false; bool не подходит как индекс.
- **null:** отсутствие значения, результат функции без return, EOF.
- **str:** неизменяемая последовательность Unicode-кодовых точек. Внутреннее хранение — UTF-8. Индекс/len считают не байты и не графемные кластеры.
- **list:** изменяемая последовательность значений любого типа, передаётся по ссылке.
- **function:** именованная/анонимная функция, замыкание или builtin.

Целочисленное `//` округляет вниз; `%` согласован с ним. Отрицательная степень может дать float. Комплексные результаты не поддерживаются. Смешанная арифметика int/float требует представимого преобразования int в float. Сравнение int/float, в отличие от такого преобразования, выполняется по точному рациональному значению float — большие целые не становятся ошибочно равными соседнему округлённому float.

`+` также конкатенирует две строки или два списка. `*` повторяет строку/список целое число раз, с любой стороны; неположительное повторение даёт пустое значение. Копирование списка при повторении/конкатенации поверхностное. Неявного склеивания строки с числом нет.

Равенство списков структурное, включая циклические списки; равенство функций — по идентичности. Сравнение порядка разрешено для чисел или двух строк. Индекс начинается с 0, отрицательный считается с конца. Выход за границы — ошибка. По индексу изменяется только список; срезов нет.

## Окружения, функции и циклы

Объявление создаёт имя в текущей области после выполнения инициализатора. Повторное объявление там же — ошибка. Во вложенной области разрешено затенение. Предварительного поднятия объявлений нет.

Присваивание меняет ближайшее существующее имя. Функция сохраняет окружение определения, а не окружение вызывающего кода. Окружения живые: последующие изменения и объявления в захваченной области доступны при последующих вызовах. Статического разрешения имён и temporal dead zone нет.

Аргументы вычисляются слева направо; число должно совпадать с параметрами. Вызов создаёт локальное окружение. `return` выходит из функции, включая вложенные циклы; без выражения и при достижении конца тела результат null. Функции можно передавать, возвращать и сохранять в списках.

Тело каждого прохода while получает новую область блока. For перебирает снимок списка или строки. Каждый проход for получает собственную переменную цикла, поэтому замыкания захватывают отдельные значения проходов. Эта переменная не выходит наружу. Изменения исходного списка не увеличивают число проходов.

## Память

C++-runtime владеет окружениями, списками и пользовательскими функциями. Ссылки между ними не используют циклическое владение `shared_ptr`. После завершения или ошибки каждой программы/команды REPL выполняется tracing mark-and-sweep от глобального окружения и последнего результата. Мёртвые циклы списков и функций освобождаются. Во время активного вычисления сборка не запускается; после завершения runtime освобождаются все оставшиеся объекты.

AST и сведения об исходнике имеют собственное управление временем жизни; определённая в REPL функция остаётся работоспособной после удаления временного объекта разобранной команды.

## Ввод, вывод и ошибки

`print` разделяет значения пробелами и завершает строку LF. Строки выводятся без кавычек; строки внутри списка — с экранированием. Bool/null выглядят как `true/false/null`. Цикл в списке обозначается `[...]`. Float выводится в кратком представлении с обратимым binary64-значением; целые float сохраняют `.0`.

`input` читает UTF-8 строку, удаляет один завершающий LF/CRLF, сохраняет другие пробелы; EOF даёт null. Необязательная строка-подсказка выводится до чтения без LF. Ошибочный UTF-8 ввода — ошибка выполнения.

Парсер проверяет весь файл до исполнения. Ошибка исполнения останавливает запуск, ранее выведенные данные остаются. Один вызов print сначала формирует ограниченное представление, затем пишет его; представление не разрастается бесконтрольно до проверки лимита. Пользовательского catch нет. В REPL ошибки не откатывают уже совершённые изменения.

Координаты — по Unicode-кодовым точкам, начиная с 1. Диагностика ограничивает длину показываемой строки и учитывает combining marks алфавита при рисовании указателя. Для неверного UTF-8 исходника сообщается причина/байт, без обещания точной позиции уже некорректного символа. Показывается до 12 мест вызовов.

## Границы реализации

- Исходник: 1 000 000 кодовых точек, UTF-8 файл не более 4 000 004 байт.
- Целое число: 4096 бит; длина битового литерала тоже ограничена 4096.
- Строка: 1 000 000 кодовых точек; список/range: 100 000 элементов.
- Параметры/аргументы: 255.
- Глубина AST: 256; глубина разбора: 512; вложенность активного исполнения AST: 1024.
- Вложенность форматирования/сравнения значений: 256.
- По умолчанию: 1 000 000 шагов, 128 вызовов, 1 048 576 байт вывода.

Шаги считаются при посещении инструкций и выражений AST, а также проходах for. `--max-depth` изменяет предел пользовательских вызовов, но не отменяет остальных ограничений вложенности. Бюджеты шагов/вывода сбрасываются перед каждой командой REPL.

Ограничения защищают от обычных случайных зависаний и чрезмерных значений. Они **не делают интерпретатор изолированной средой безопасности для недоверенного кода**.
